# localized-cli 规范

## 目的
待定 - 由归档变更 xgit-setup-i18n-and-annotation 创建。归档后请更新目的。
## 需求
### 需求:CLI 文案必须通过语言资源解析
`xgit` 必须通过外部语言资源解析 help、错误信息、状态提示和 setup 界面文案，禁止在命令实现代码中硬编码最终展示给用户的中文或英文文本。

#### 场景:按配置语言展示中文 help
- **当** 用户的有效语言为 `zh-CN` 并运行 `xgit help`
- **那么** 系统必须输出中文的命令说明、参数说明和状态提示

#### 场景:按配置语言展示英文 help
- **当** 用户的有效语言为 `en-US` 并运行 `xgit help`
- **那么** 系统必须输出英文的命令说明、参数说明和状态提示

### 需求:setup 界面必须完整遵循有效语言
当有效语言为中文或英文时，setup 界面的页面标题、字段标签、操作提示和导航提示必须全部使用同一语言资源，不得出现菜单为中文而内容区域仍为英文的混合显示。

#### 场景:中文设置界面完整显示中文
- **当** 全局或项目配置将有效语言设置为 `zh-CN` 并且用户运行 `xgit setup`
- **那么** 系统必须以中文显示设置界面的标题、说明、字段标签和操作提示

### 需求:语言选择必须遵循配置优先与系统回退
`xgit` 必须按统一优先级决定当前语言，至少支持项目配置、全局配置和系统语言的回退链路，不得依赖命令行临时语言选项。

#### 场景:项目配置覆盖全局语言
- **当** 全局配置将语言设置为 `en-US`，但当前项目配置将语言设置为 `zh-CN`
- **那么** 系统必须在该项目中使用中文资源输出 help 和消息

#### 场景:无显式配置时回退系统语言
- **当** 用户未在项目或全局配置中设置语言
- **那么** 系统必须根据系统语言决定默认资源，并在无法识别时使用内置默认语言

### 需求:help 必须展示功能关闭状态
当某项功能被配置关闭时，`xgit help` 必须让用户能够看到该功能当前处于禁用状态。

#### 场景:push 功能被关闭
- **当** 项目配置将 `push` 功能设为关闭并且用户运行 `xgit help`
- **那么** 系统必须在 `push` 命令说明中标明该功能当前已关闭

### 需求:CLI 不得暴露独立语言选项
`xgit` 的公开命令行接口不得暴露 `--lang` 或等价的临时语言切换 option；语言必须通过 setup 所写入的配置决定。

#### 场景:查看帮助选项列表
- **当** 用户运行 `xgit help` 或查看任一子命令的 options
- **那么** 系统不得显示 `--lang` 语言选项
