## 需求
### 需求:系统必须提供交互式设置界面
`xgit` 必须提供一个基于 ratatui 的交互式设置界面，用于浏览和修改 `xgit` 的配置项。

#### 场景:打开全局设置界面
- **当** 用户运行 `xgit setup`
- **那么** 系统必须打开用于编辑全局配置的交互式设置界面

### 需求:设置界面必须采用层级导航
设置界面必须允许用户通过上下方向键选择主功能页面，通过 Enter 进入当前页面，并通过 ESC 返回上一级；主页面切换不得依赖 Tab 作为唯一方式。

#### 场景:进入主功能页面
- **当** 用户位于设置界面的主页面列表并使用上下方向键选中某个功能页面后按 Enter
- **那么** 系统必须进入该功能页面并展示该页面的字段列表

#### 场景:从子页面返回上一级
- **当** 用户位于某个功能页面内部并按下 ESC
- **那么** 系统必须返回主页面列表，而不是直接退出设置界面

### 需求:系统必须支持项目级设置界面
`xgit setup --project` 必须编辑当前 Git 工作区根目录下的 `.xgit/config.toml`。

#### 场景:在 Git 工作区中打开项目设置
- **当** 用户位于 Git 工作区内并运行 `xgit setup --project`
- **那么** 系统必须打开项目级设置界面并将保存目标设为当前工作区根目录下的 `.xgit/config.toml`

#### 场景:在非 Git 工作区中打开项目设置
- **当** 用户位于非 Git 工作区目录并运行 `xgit setup --project`
- **那么** 系统必须拒绝打开项目设置并提示当前目录不在 Git 工作区中

### 需求:设置界面必须暴露核心配置栏目
`xgit` 必须至少允许用户查看和修改功能使能开关、push 设置占位项、注释策略设置、代码文件类型、注释渲染行为和身份信息；在注释策略设置中，系统必须暴露 `add`、`modify` 和 `del` 各自的起始模板与结束模板配置入口。

#### 场景:修改注释策略相关配置
- **当** 用户进入设置界面的注释策略栏目
- **那么** 系统必须允许用户编辑运行时表单字段、引用类型定义、代码文件类型选择、注释渲染行为开关、`add` / `modify` / `del` 三类注释块各自的起始模板和结束模板、日期格式，以及旧代码展示策略及其模式相关字段
- **并且** 用户不得只能通过模板字符串间接表达日期格式或旧代码展示风格

### 需求:退出设置界面前必须处理未保存修改
当用户在设置界面中存在未保存修改时，系统必须在退出前提示用户是否保存，而不是直接丢弃或静默保存。

#### 场景:有未保存修改时退出设置
- **当** 用户在设置界面中修改了配置但尚未保存，并在主页面按下 ESC 请求退出
- **那么** 系统必须弹出保存确认，并允许用户选择保存后退出、放弃修改退出或取消退出

### 需求:代码文件类型必须支持层级化多选
设置界面的注释配置必须提供“代码文件类型”层级化多选入口，禁止要求用户把 `pattern=renderer;...` 原始字符串作为主要编辑方式。代码文件类型入口必须按语言分类展示子项，并支持分类层与扩展名层之间的层级导航。

#### 场景:打开代码文件类型选择器
- **当** 用户在设置界面的注释配置栏目中选中“代码文件类型”并按下 Enter
- **那么** 系统必须打开一个结构化选择器，至少展示 `C/C++`、`Java`、`JavaScript`、`Rust` 和 `Kotlin` 五个分类
- **并且** 系统必须默认将 `C/C++` 和 `Java` 标记为已选中分类

#### 场景:在分类层进入扩展名子项
- **当** 用户位于代码文件类型选择器的分类层并选中某个语言分类后按下 Enter
- **那么** 系统必须进入该分类的扩展名列表，以便用户单独启用或关闭具体文件类型

#### 场景:分类层显示部分选中状态
- **当** 某个语言分类下仅有部分扩展名被启用
- **那么** 系统必须在分类层将该分类显示为部分选中状态，而不是把它误显示为全选或未选中

### 需求:设置界面必须为旧版注释策略提供可迁移的模板编辑入口
当用户打开仍使用旧 `annotate.policies.*` 的配置时，设置界面必须把它们归一化为可编辑的起始模板和结束模板字段展示给用户，禁止要求用户先手工改写配置文件后才能继续使用设置界面。

#### 场景:打开仅包含旧版策略的项目配置
- **当** 用户打开一个只配置了旧 `annotate.policies.modify` 的项目设置
- **那么** 注释策略栏目必须显示可编辑的 `modify` 起始模板字段和值
- **并且** 系统必须同时显示兼容生成的 `modify` 结束模板字段，而不是把结束模板留空或隐藏

### 需求:设置界面必须提供结构化的旧代码展示策略编辑入口
当用户在 setup 中编辑注释策略时，系统必须允许用户以结构化字段配置旧代码展示策略，而不是要求用户通过 `modify` / `del` 模板手工编排 `{old}`、`// old:` 或 `/* */` 语法。

#### 场景:选择行注释旧代码策略
- **当** 用户把旧代码展示策略切换为 `line_comment`
- **那么** 设置界面必须允许用户编辑布局、标题文本、内容前缀和内容后缀等字段
- **并且** 用户不得必须直接修改 `modify` 或 `del` 模板来实现“每行 old:”风格

#### 场景:选择块注释旧代码策略
- **当** 用户把旧代码展示策略切换为 `block_comment`
- **那么** 设置界面必须允许用户编辑块注释标题和内容前缀等字段
- **并且** 用户不得必须手工写入完整的 `/* */` 旧代码块模板
