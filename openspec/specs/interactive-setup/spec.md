# interactive-setup 规范

## 目的
待定 - 由归档变更 xgit-setup-i18n-and-annotation 创建。归档后请更新目的。
## 需求
### 需求:系统必须提供交互式设置界面
`xgit` 必须提供一个基于 ratatui 的交互式设置界面，用于浏览和修改 `xgit` 的配置项。

#### 场景:打开全局设置界面
- **当** 用户运行 `xgit setup`
- **那么** 系统必须打开用于编辑全局配置的交互式设置界面

### 需求:设置界面必须采用层级导航
设置界面必须允许用户在任意当前层级通过上下方向键选择菜单项，通过 Enter 进入子菜单或打开当前项的编辑入口，通过 Space 切换布尔项或多选项，并通过 ESC 返回上一级；主页面切换不得依赖双栏焦点切换或 Tab 作为唯一方式。

#### 场景:进入当前选中的子菜单
- **当** 用户位于设置界面的某一层菜单，并使用上下方向键选中某个子菜单项后按下 Enter
- **那么** 系统必须进入该子菜单并展示该层级的菜单项

#### 场景:从任意子菜单返回上一级
- **当** 用户位于某个子菜单内部并按下 ESC
- **那么** 系统必须返回上一级菜单
- **并且** 系统不得直接退出整个设置界面，除非用户当前已经位于根菜单

### 需求:系统必须支持项目级设置界面
`xgit setup --project` 必须编辑当前 Git 工作区根目录下的 `.xgit/config.toml`。

#### 场景:在 Git 工作区中打开项目设置
- **当** 用户位于 Git 工作区内并运行 `xgit setup --project`
- **那么** 系统必须打开项目级设置界面并将保存目标设为当前工作区根目录下的 `.xgit/config.toml`

#### 场景:在非 Git 工作区中打开项目设置
- **当** 用户位于非 Git 工作区目录并运行 `xgit setup --project`
- **那么** 系统必须拒绝打开项目设置并提示当前目录不在 Git 工作区中

### 需求:设置界面必须暴露核心配置栏目
`xgit` 必须至少允许用户查看和修改功能使能开关、push 设置占位项、注释设置、代码文件类型、注释渲染行为和身份信息；功能开关必须至少覆盖 `push`、`annotate`、`reset`、`checkout-remote` 与 `completion`，而注释设置必须以子菜单形式暴露引用与表单、代码文件类型、渲染行为、`add` / `modify` / `del` 模板，以及旧代码处理配置入口。

#### 场景:修改功能开关配置
- **当** 用户进入设置界面的功能开关栏目
- **那么** 系统必须允许用户查看并切换 `push`、`annotate`、`reset`、`checkout-remote` 与 `completion` 的启用状态

#### 场景:通过注释设置子菜单修改模板与旧代码策略
- **当** 用户进入设置界面的 `注释设置` 栏目
- **那么** 系统必须允许用户继续进入 `新增格式`、`修改格式`、`删除格式` 和 `旧代码处理` 等子菜单
- **并且** 用户不得只能在同一页长字段列表中完成全部注释相关配置

### 需求:退出设置界面前必须处理未保存修改
当用户在设置界面中存在未保存修改时，系统必须在退出前提示用户是否保存，而不是直接丢弃或静默保存。

#### 场景:有未保存修改时退出设置
- **当** 用户在设置界面中修改了配置但尚未保存，并在主页面按下 ESC 请求退出
- **那么** 系统必须弹出保存确认，并允许用户选择保存后退出、放弃修改退出或取消退出

### 需求:代码文件类型必须支持层级化多选
设置界面的注释配置必须提供“代码文件类型”层级化多选入口，禁止要求用户把 `pattern=renderer;...` 原始字符串作为主要编辑方式。代码文件类型入口必须作为标准子菜单参与层级导航，按语言分类展示子项，并支持分类层与扩展名层之间的进入、返回和多选切换。

#### 场景:通过标准子菜单进入代码文件类型选择
- **当** 用户在 `注释设置` 中选中“代码文件类型”并按下 Enter
- **那么** 系统必须进入代码文件类型子菜单，至少展示 `C/C++`、`Java`、`JavaScript`、`Rust` 和 `Kotlin` 五个分类
- **并且** 该入口必须遵循与其他 setup 子菜单一致的 Enter / ESC 导航语义

#### 场景:在分类层与扩展名层之间往返
- **当** 用户位于代码文件类型分类层并选中某个语言分类后按下 Enter
- **那么** 系统必须进入该分类的扩展名列表
- **并且** 用户在扩展名层按下 ESC 时，系统必须返回分类层而不是直接关闭整个 setup

### 需求:代码文件类型目录必须覆盖现有已接入语言的常见代码扩展名
设置界面的代码文件类型选择器必须为当前已接入语言分类提供完整的常见代码扩展名集合，禁止只保留演示级最小样本。系统必须至少提供以下内置条目：`C/C++` 的 `.c`、`.h`、`.cpp`、`.cc`、`.cxx`、`.hpp`、`.hh`、`.hxx`、`.ipp`、`.inl`、`.tpp`，`Java` 的 `.java`，`JavaScript` 的 `.js`、`.mjs`、`.cjs`、`.jsx`，`Rust` 的 `.rs`，以及 `Kotlin` 的 `.kt`、`.kts`。

#### 场景:打开 C/C++ 分类查看补齐后的常见扩展名
- **当** 用户在设置界面的“代码文件类型”选择器中进入 `C/C++` 分类
- **那么** 系统必须展示至少 `.c`、`.h`、`.cpp`、`.cc`、`.cxx`、`.hpp`、`.hh` 和 `.hxx` 这些常见代码扩展名
- **并且** `*.hpp` 不得继续因为目录未内置而只能依赖手工自定义规则

#### 场景:打开 JavaScript 与 Kotlin 分类查看脚本变体
- **当** 用户分别进入 `JavaScript` 和 `Kotlin` 分类
- **那么** `JavaScript` 分类必须至少包含 `.js`、`.mjs`、`.cjs`、`.jsx`
- **并且** `Kotlin` 分类必须至少包含 `.kt` 和 `.kts`

### 需求:代码文件类型目录必须排除非代码文件规则
设置界面的内置代码文件类型目录必须只包含代码文件规则，禁止把构建文件、配置文件或固定文件名脚本作为内置代码类型混入其中。

#### 场景:查看内置代码文件类型目录时不出现 Android.bp
- **当** 用户打开设置界面的“代码文件类型”选择器并浏览内置分类
- **那么** 系统不得把 `Android.bp` 作为任一内置代码文件类型条目展示出来
- **并且** 系统不得要求用户把非代码文件和代码文件放在同一套默认选择目录中

### 需求:设置界面必须为旧版注释策略提供可迁移的模板编辑入口
当用户打开仍使用旧 `annotate.policies.*` 的配置时，设置界面必须把它们归一化为可编辑的起始模板和结束模板字段展示给用户，禁止要求用户先手工改写配置文件后才能继续使用设置界面。

#### 场景:打开仅包含旧版策略的项目配置
- **当** 用户打开一个只配置了旧 `annotate.policies.modify` 的项目设置
- **那么** 注释策略栏目必须显示可编辑的 `modify` 起始模板字段和值
- **并且** 系统必须同时显示兼容生成的 `modify` 结束模板字段，而不是把结束模板留空或隐藏

### 需求:设置界面必须提供结构化的旧代码展示策略编辑入口
当用户在 setup 中编辑注释策略时，系统必须允许用户以结构化字段配置旧代码展示策略，而不是要求用户通过 `modify` / `del` 模板手工编排 `{old}`、`// old:` 或 `/* */` 语法。

#### 场景:选择行注释旧代码策略
- **当** 用户把旧代码展示策略切换为 `line_comment`
- **那么** 设置界面必须允许用户编辑布局、标题文本、内容前缀和内容后缀等字段
- **并且** 用户不得必须直接修改 `modify` 或 `del` 模板来实现“每行 old:”风格

#### 场景:选择块注释旧代码策略
- **当** 用户把旧代码展示策略切换为 `block_comment`
- **那么** 设置界面必须允许用户编辑块注释标题和内容前缀等字段
- **并且** 用户不得必须手工写入完整的 `/* */` 旧代码块模板

### 需求:设置界面必须以单栏树形菜单呈现当前层级
设置界面必须以单栏 menuconfig 式列表呈现当前层级的菜单项，禁止要求用户同时在固定左栏栏目列表和右栏字段列表之间切换焦点；界面必须明确显示当前菜单路径，帮助用户理解自己位于哪一层。

#### 场景:根菜单只显示当前层级列表
- **当** 用户运行 `xgit setup`
- **那么** 系统必须先显示根层级的单栏菜单列表
- **并且** 界面必须显示当前路径信息，而不是同时展示一个固定栏目栏和一个独立字段栏

#### 场景:进入子菜单后更新当前路径
- **当** 用户在根菜单选中 `注释设置` 并按下 Enter
- **那么** 系统必须进入 `注释设置` 子菜单
- **并且** 界面显示的当前路径必须更新为包含 `注释设置` 的层级路径

### 需求:设置界面必须提供结构化的注释字段与引用类型编辑入口
设置界面必须为注释运行时上下文字段提供结构化编辑入口，允许用户查看和修改字段定义及其候选类型集合；禁止要求用户继续通过原始 CSV 字符串直接编辑字段顺序或引用类型列表。

#### 场景:在引用与表单子菜单中编辑字段定义
- **当** 用户进入 `注释设置 > 引用与表单`
- **那么** 系统必须允许用户浏览当前启用的注释字段定义
- **并且** 系统不得只显示 `form_fields (csv)` 一类原始字符串输入框

#### 场景:在引用与表单子菜单中编辑引用类型集合
- **当** 用户进入 `注释设置 > 引用与表单 > 引用类型`
- **那么** 系统必须允许用户维护引用类型候选集合
- **并且** 系统不得要求用户直接手工输入逗号分隔字符串才能完成配置

### 需求:设置界面必须说明注释模板与旧代码处理的依赖关系
设置界面必须在 `修改格式`、`删除格式` 和 `旧代码处理` 相关帮助内容中明确说明各自的生效条件与依赖关系，禁止只展示菜单名称而不解释哪些组合会真正影响 annotate 结果。

#### 场景:查看修改格式帮助时看到旧代码关闭后的行为
- **当** 用户在 setup 中选中 `修改格式`
- **并且** 旧代码处理当前处于关闭状态
- **那么** 帮助栏必须明确说明修改注释仍可生效
- **并且** 帮助栏必须明确说明不会输出 `old` 字段或旧代码内容

#### 场景:查看删除格式帮助时看到旧代码依赖
- **当** 用户在 setup 中选中 `删除格式`
- **那么** 帮助栏必须明确说明删除格式依赖旧代码处理
- **并且** 帮助栏必须明确指出只有删除格式与旧代码处理同时开启时删除块格式化才会生效

#### 场景:查看旧代码处理帮助时看到其不会替代模板开关
- **当** 用户在 setup 中选中 `旧代码处理`
- **那么** 帮助栏必须明确说明它只控制旧代码展示
- **并且** 帮助栏必须明确说明它不会自动开启 `修改格式` 或 `删除格式`

### 需求:设置界面的关联值型开关必须保留已编辑配置值
对于同时拥有启用状态和子配置值的 setup 项，系统在关闭该项时必须只改变其生效状态，禁止把用户已编辑的模板文本、模式选择或其他关联值恢复为默认值、空值或兼容回退值；当用户重新开启该项时，系统必须恢复到关闭前最后一次保存的关联值。

#### 场景:关闭并重新开启模板开关后保留模板文本
- **当** 用户在 setup 中编辑了 `新增格式`、`修改格式` 或 `删除格式` 的起始模板或结束模板
- **并且** 用户随后关闭该模板开关并再次重新开启
- **那么** 系统必须保留用户此前编辑过的模板文本
- **并且** 系统禁止把该模板恢复为默认模板

#### 场景:关闭并重新开启旧代码处理后保留之前选择的模式
- **当** 用户在 setup 中把 `旧代码处理` 显式设置为 `line_comment` 或 `block_comment`
- **并且** 用户随后关闭该开关并再次重新开启
- **那么** 系统必须恢复到关闭前最后一次选中的旧代码处理模式
- **并且** 系统禁止固定回退到 legacy 模式或其他默认模式

#### 场景:关闭关联值型开关后保存并重载仍保留配置值
- **当** 用户关闭某个带有关联配置值的 setup 开关并保存配置
- **并且** 用户之后重新打开 setup 并重新开启该项
- **那么** 系统必须仍然保留关闭前最后一次保存的关联值
- **并且** 系统禁止仅在当前会话内保持该值而在重载后丢失

### 需求:设置界面必须为当前交互状态显示上下文化帮助栏
设置界面必须在帮助栏中显示与当前高亮项或当前交互状态对应的说明文本，并且必须在单独一行显示该状态下可用的快捷键；禁止只显示固定通用提示，或在状态切换后继续显示不适用的快捷键。

#### 场景:根菜单选中通用设置时显示当前项帮助
- **当** 用户位于设置界面的根菜单，并将光标停留在 `通用设置`
- **那么** 帮助栏第一行必须说明 `通用设置` 用于配置语言、功能开关等通用项目
- **并且** 帮助栏第二行必须列出当前可用快捷键，至少包含保存、退出、上下选择和进入子菜单

#### 场景:文本编辑态覆盖普通菜单帮助
- **当** 用户在任意文本字段上按 Enter 进入编辑器
- **那么** 帮助栏必须切换为编辑态说明和编辑快捷键
- **并且** 帮助栏不得继续显示普通菜单态的“进入子菜单”或“空格切换”提示

#### 场景:退出确认态覆盖普通菜单帮助
- **当** 用户存在未保存修改并触发退出确认
- **那么** 帮助栏必须说明当前正在确认退出方式
- **并且** 帮助栏必须只显示确认态可用的上下选择、确认和取消快捷键

### 需求:帮助栏必须保留可见正文区域
设置界面布局必须为帮助栏保留足够的正文高度，使帮助栏在常见终端尺寸下至少能够同时显示一行说明和一行快捷键；禁止只渲染边框而看不到帮助正文。

#### 场景:默认 setup 界面可见显示两行帮助正文
- **当** 用户在常见终端尺寸下打开 `xgit setup`
- **那么** 帮助栏必须能实际显示说明行和快捷键行
- **并且** 用户不得只能看到一个空白的帮助边框
