## 为什么

`xgit annotate` 目前会把注释固定插在行首，并且默认包裹变更块中的空行，导致生成结果和原代码排版不一致，降低了自动化注释在真实代码中的可读性。与此同时，`xgit setup` 仍然把代码文件类型暴露为 `pattern=renderer;...` 的原始字符串编辑方式，这和现有 menuconfig 风格界面不一致，也不利于后续扩展更多语言分类。

## 变更内容

- 为注释渲染新增可配置行为，允许用户决定注释是否跟随被包裹代码的缩进对齐。
- 为注释渲染新增可配置行为，允许用户决定是否包裹变更块中的空白行，而不是固定把空行包含在注释块内部。
- 调整 `xgit setup` 的注释配置界面，把“文件规则 (pattern=renderer;...)”替换为更直观的“代码文件类型”结构化选择。
- 为代码文件类型选择引入按语言分类的层级导航，支持在分类层显示全选、部分选中和未选中的状态，并在分类内部选择具体扩展名。
- 在第一阶段预置 `C/C++`、`Java`、`JavaScript`、`Rust` 和 `Kotlin` 五个分类，其中默认启用 `C/C++` 和 `Java`，并保持未来继续扩展语言分类的能力。
- 保持现有文件规则到渲染器的执行模型不变，但要求 setup 负责把结构化语言/扩展名选择映射回有效的注释文件规则。

### 修改功能
- `interactive-setup`: 注释配置栏目需要支持层级化的代码文件类型选择，并暴露注释缩进与空行包裹相关开关，替代原始文件规则字符串编辑体验。
- `annotation-normalization`: 注释渲染结果需要受缩进对齐和空行包裹策略控制，并根据 setup 维护的代码文件类型集合决定哪些文件参与 C-like 渲染器分发。

## 影响

- `xgit/src/setup_ui.rs` 将从单纯的文本编辑模式扩展为支持层级选择弹窗和部分选中状态的交互模型。
- `xgit/src/config.rs` 与默认配置需要增加注释渲染选项，并承载结构化代码文件类型选择的配置表达。
- `xgit/src/annotate.rs` 的渲染逻辑需要根据有效配置决定注释缩进和空行包裹行为。
- 语言资源、setup 交互测试、配置读写测试和注释渲染测试都需要补充新的回归覆盖。
