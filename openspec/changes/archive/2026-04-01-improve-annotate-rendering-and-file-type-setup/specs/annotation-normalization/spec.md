## 新增需求

### 需求:注释渲染必须支持缩进对齐策略
系统必须允许通过有效配置决定注释是否跟随被包裹代码的缩进对齐；当该策略启用时，注释起止行必须与对应代码块的有效缩进保持一致，而不是固定顶格输出。

#### 场景:启用缩进对齐后渲染新增代码块
- **当** 有效配置启用了注释缩进对齐，并且某个新增代码块本身带有前导缩进
- **那么** 系统必须让该代码块前后的注释行使用与该代码块一致的有效缩进

### 需求:注释渲染必须支持空白行包裹策略
系统必须允许通过有效配置决定注释块是否包裹变更中的空白行；当关闭空白行包裹时，注释块必须只围绕有效代码部分建立包裹边界，而不得因为空白行扩大包裹范围。

#### 场景:关闭空白行包裹后保留外围空白行
- **当** 有效配置关闭了空白行包裹，并且某个新增代码块前后包含空白行
- **那么** 系统必须保留这些空白行在文件中的原始位置
- **并且** 注释块必须只包裹该变更中的有效代码部分

## 修改需求

### 需求:系统必须支持文件规则到渲染器的映射
系统必须允许通过配置或 setup 维护的代码文件类型选择将文件类型映射到不同的注释渲染器，并在渲染器未实现时明确提示或跳过。

#### 场景:处理已启用的行注释语言文件
- **当** 目标文件命中了当前已启用的内置代码文件类型，并且该类型使用行注释块渲染器
- **那么** 系统必须使用行注释块渲染器生成 `add`、`modify` 或 `del` 注释

#### 场景:命中未实现的特殊渲染器
- **当** 目标文件命中了某个尚未实现的渲染器类型
- **那么** 系统必须明确提示该文件当前未被自动处理，而不是静默忽略
