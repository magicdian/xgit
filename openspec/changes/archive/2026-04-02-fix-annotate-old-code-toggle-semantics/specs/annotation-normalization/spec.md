## 修改需求

### 需求:系统必须按改动类型生成规范化注释
系统必须识别 `add`、`modify` 和 `del` 三类改动，并只在对应模板开关及其前置条件满足时生成规范化注释块；系统禁止因为旧代码处理开启、模板文本包含 `{old}` 或 legacy fallback 仍绕过模板开关。

#### 场景:关闭旧代码处理时仍渲染 modify 注释
- **当** 某个变更块同时包含删除旧代码和新增新代码
- **并且** `modify` 模板处于开启状态
- **并且** 旧代码处理被显式关闭
- **那么** 系统必须按 `modify` 模板生成修改注释
- **并且** 最终输出必须不包含 `old=` 字段、legacy `old:` 注释或任何旧代码正文

#### 场景:关闭 modify 模板时不得因旧代码处理而渲染修改块
- **当** 某个变更块同时包含删除旧代码和新增新代码
- **并且** `modify` 模板处于关闭状态
- **并且** 旧代码处理处于开启状态
- **那么** 系统必须不为该变更块生成 `modify` 注释
- **并且** 系统必须不附加任何旧代码注释或旧代码字段

#### 场景:删除块仅在删除模板和旧代码处理都开启时渲染
- **当** 某个变更块只包含删除旧代码
- **并且** `del` 模板处于开启状态
- **并且** 旧代码处理处于开启状态
- **那么** 系统必须按 `del` 模板生成删除注释
- **并且** 删除注释中的旧代码内容必须遵循当前旧代码展示策略

#### 场景:删除块缺少旧代码前置条件时进入未格式化结果
- **当** 某个变更块只包含删除旧代码
- **并且** `del` 模板处于开启状态
- **并且** 旧代码处理被显式关闭
- **那么** 系统必须不生成删除注释
- **并且** 系统必须把该删除候选计入未格式化结果
- **并且** 原因必须明确表示删除格式依赖旧代码处理

### 需求:系统必须支持显式的旧代码展示策略
系统必须允许通过有效配置为 `modify` 和 `del` 注释块声明旧代码展示策略，并在显式策略存在时优先使用该策略；当显式策略关闭旧代码展示时，系统必须清理模板中与旧代码相关的占位结果，禁止再通过 `{old}` 占位符或 hard-coded fallback 输出旧代码。

#### 场景:关闭旧代码展示
- **当** 有效配置将旧代码展示策略设为 `none`
- **那么** `modify` 或 `del` 注释块中必须不包含旧代码记录
- **并且** 系统不得因为模板中包含 `{old}` 或旧兼容逻辑再次输出旧代码

#### 场景:关闭旧代码展示时清理模板字段残留
- **当** 有效配置将旧代码展示策略设为 `none`
- **并且** `modify` 起始模板仍包含 `old={old}` 一类旧代码占位片段
- **那么** 系统必须从最终输出中移除该旧代码占位结果
- **并且** 系统不得留下 `old=`、空白占位或其他无效残留文本

#### 场景:按行注释逐行展示旧代码
- **当** 有效配置将旧代码展示策略设为 `line_comment`，布局设为 `per_line`，且内容前缀设为 `old: `
- **那么** 变更块中的每一行旧代码都必须以对应渲染器的行注释语法输出
- **并且** 每一行旧代码前都必须附加 `old: ` 前缀

#### 场景:使用块注释展示旧代码
- **当** 有效配置将旧代码展示策略设为 `block_comment`，并把标题设为 `cover old codes`
- **那么** 系统必须使用对应渲染器的块注释边界包裹旧代码
- **并且** 旧代码块的首行必须包含 `cover old codes` 备注

#### 场景:未配置显式旧代码策略时保持兼容语义
- **当** 有效配置未定义显式旧代码展示策略
- **并且** 当前变更类型自身的模板开关仍处于开启状态
- **并且** `modify` 起始模板仍包含 `{old}`
- **那么** 系统必须继续按 legacy `{old}` 语义展开旧代码
- **并且** 系统不得额外附加新的结构化旧代码块
