## 上下文

当前 setup 界面的帮助栏存在两个独立问题：

- `active_help()` 在普通菜单态只返回固定的 `setup.help.menu_actions`，不会根据当前高亮项切换说明，因此用户无法知道“当前选中的这个菜单项是干什么的”。
- `draw()` 给帮助栏分配的是 `Constraint::Length(2)`，在带边框的 `Paragraph` 中会把两行都消耗在上下边框上，正文高度变成 `0`，所以帮助栏即使有字符串也很容易看起来是空白。

setup 界面已经拥有完整的层级菜单状态：`SetupState` 里有当前栈、当前选择项，`current_items()` 能拿到当前层级的 `MenuItem`。因此这次变更不需要重做导航模型，只需要在现有菜单模型上补一层“帮助内容生成”和“帮助区布局约束”。

## 目标 / 非目标

**目标：**

- 让帮助栏在普通菜单态展示当前选中项的意义，而不是固定通用提示。
- 让帮助栏在第二行展示当前状态下真实可用的快捷键，避免展示当前状态不可用的操作。
- 让帮助栏在常见终端高度下始终有可见正文空间，至少能同时显示一行说明和一行快捷键。
- 保持现有 menuconfig 式导航结构不变，复用现有 i18n 体系和菜单状态。

**非目标：**

- 不重做 setup 整体布局或改回双栏界面。
- 不引入新的弹窗式帮助、分页式说明或鼠标交互。
- 不在本次变更中补完所有设置项的长篇文档，只解决 setup 内即时帮助问题。

## 决策

### 1. 用结构化帮助模型替代单一帮助字符串

帮助栏将从“返回一个字符串”改为“返回两段结构化内容”：`summary`（当前项说明）和 `shortcuts`（当前快捷键列表）。渲染时按两行输出，而不是把所有信息塞进一段文案里。

这样可以稳定满足你提出的目标格式：第一行解释当前项意义，第二行列出快捷键。

备选方案：

- 继续使用单条本地化字符串：会让“说明”和“快捷键”耦合在一起，难以按状态组合，也不利于后续扩展。

### 2. 普通菜单态按“当前选中项”生成帮助，编辑态和确认态覆盖普通帮助

帮助内容生成分三类状态：

- 普通菜单态：读取 `selected_item()`，为当前高亮项生成说明和快捷键。
- 文本编辑态：忽略菜单选择，直接显示编辑器说明和编辑快捷键。
- 退出确认态：忽略菜单选择，直接显示退出确认说明和确认快捷键。

这与当前交互模型一致，也能避免用户在编辑或确认弹窗中看到与当前菜单无关的提示。

备选方案：

- 只按 `MenuId` 生成菜单级帮助：无法区分同一菜单下不同字段或不同类型条目的操作差异。

### 3. 说明文本使用“显式文案 + 回退文案”策略

对于根菜单、主要子菜单和高频配置项，新增专门的帮助说明文案键；如果某个条目暂时没有独立说明，则回退为基于当前菜单标题和条目类型生成的通用说明，确保帮助栏不会再次出现空白或无意义占位。

这能在控制改动规模的同时，优先覆盖用户真正会经过的路径，例如：

- 根菜单中的“通用设置 / 身份信息 / 注释设置”
- 通用设置中的“语言 / 功能开关 / Push”
- 注释设置中的“引用与表单 / 代码文件类型 / 渲染行为 / 新增格式 / 修改格式 / 删除格式 / 旧代码处理”

备选方案：

- 强制每个菜单项都必须先补一个专门文案才允许渲染：实现成本高，而且会让后续新增菜单项更容易漏配。

### 4. 快捷键按“当前条目类型 / 当前状态”组合，而不是写死一条固定提示

快捷键列表将按当前可执行动作来组合：

- 纯子菜单项：显示保存、退出/返回、上下移动、回车进入。
- 可空格切换的布尔项或多选项：显示保存、返回、上下移动、空格切换。
- 文本项：显示保存、返回、上下移动、回车进入编辑。
- 编辑态：显示回车保存、ESC 取消、Backspace 删除。
- 退出确认态：显示上下选择、回车确认、ESC 取消。

这样帮助栏只展示当前真的能用的按键，不再出现“看得到但按了没效果”的提示。

备选方案：

- 为每个菜单项维护完整快捷键句子：文案重复太多，维护成本高。

### 5. 帮助栏布局固定保留两行正文高度

界面布局将把帮助栏高度从当前的 `2` 调整为至少 `4`（上下边框 + 两行正文），确保默认窗口高度下第一行说明和第二行快捷键都能实际渲染出来。状态栏保持现有独立区域，菜单区继续占用剩余空间。

备选方案：

- 动态根据文本高度扩展帮助栏：实现更复杂，而且当前帮助目标明确就是两行，不需要额外自适应策略。

## 风险 / 权衡

- [部分条目仍可能缺少专门帮助文案] → 通过通用回退文案兜底，避免帮助栏为空；后续可继续按菜单项补充精确文案。
- [帮助栏增加高度会压缩菜单可视区域] → 只增加到两行正文的最小可用高度，优先保证帮助可见，同时把菜单区保留为 `Min` 区域。
- [中英文文案长度不一致，可能在较窄终端中换行] → 文案保持短句，快捷键统一采用 `[key] 动作` 形式，减少无效字符占用。

## Migration Plan

此变更仅影响本地 TUI 渲染和文案资源，不涉及配置文件结构迁移，也不需要用户手工调整已有配置。

## Open Questions

- 暂无阻塞性开放问题。实现阶段只需在代码里确认哪些菜单项采用专门文案，哪些菜单项走回退说明即可。
