## 新增需求

### 需求:设置界面必须以单栏树形菜单呈现当前层级
设置界面必须以单栏 menuconfig 式列表呈现当前层级的菜单项，禁止要求用户同时在固定左栏栏目列表和右栏字段列表之间切换焦点；界面必须明确显示当前菜单路径，帮助用户理解自己位于哪一层。

#### 场景:根菜单只显示当前层级列表
- **当** 用户运行 `xgit setup`
- **那么** 系统必须先显示根层级的单栏菜单列表
- **并且** 界面必须显示当前路径信息，而不是同时展示一个固定栏目栏和一个独立字段栏

#### 场景:进入子菜单后更新当前路径
- **当** 用户在根菜单选中 `注释设置` 并按下 Enter
- **那么** 系统必须进入 `注释设置` 子菜单
- **并且** 界面显示的当前路径必须更新为包含 `注释设置` 的层级路径

### 需求:设置界面必须提供结构化的注释字段与引用类型编辑入口
设置界面必须为注释运行时上下文字段提供结构化编辑入口，允许用户查看和修改字段定义及其候选类型集合；禁止要求用户继续通过原始 CSV 字符串直接编辑字段顺序或引用类型列表。

#### 场景:在引用与表单子菜单中编辑字段定义
- **当** 用户进入 `注释设置 > 引用与表单`
- **那么** 系统必须允许用户浏览当前启用的注释字段定义
- **并且** 系统不得只显示 `form_fields (csv)` 一类原始字符串输入框

#### 场景:在引用与表单子菜单中编辑引用类型集合
- **当** 用户进入 `注释设置 > 引用与表单 > 引用类型`
- **那么** 系统必须允许用户维护引用类型候选集合
- **并且** 系统不得要求用户直接手工输入逗号分隔字符串才能完成配置

## 修改需求

### 需求:设置界面必须采用层级导航
设置界面必须允许用户在任意当前层级通过上下方向键选择菜单项，通过 Enter 进入子菜单或打开当前项的编辑入口，通过 Space 切换布尔项或多选项，并通过 ESC 返回上一级；主页面切换不得依赖双栏焦点切换或 Tab 作为唯一方式。

#### 场景:进入当前选中的子菜单
- **当** 用户位于设置界面的某一层菜单，并使用上下方向键选中某个子菜单项后按下 Enter
- **那么** 系统必须进入该子菜单并展示该层级的菜单项

#### 场景:从任意子菜单返回上一级
- **当** 用户位于某个子菜单内部并按下 ESC
- **那么** 系统必须返回上一级菜单
- **并且** 系统不得直接退出整个设置界面，除非用户当前已经位于根菜单

### 需求:设置界面必须暴露核心配置栏目
`xgit` 必须至少允许用户查看和修改功能使能开关、push 设置占位项、注释设置、代码文件类型、注释渲染行为和身份信息；功能开关必须至少覆盖 `push`、`annotate`、`reset`、`checkout-remote` 与 `completion`，而注释设置必须以子菜单形式暴露引用与表单、代码文件类型、渲染行为、`add` / `modify` / `del` 模板，以及旧代码处理配置入口。

#### 场景:修改功能开关配置
- **当** 用户进入设置界面的功能开关栏目
- **那么** 系统必须允许用户查看并切换 `push`、`annotate`、`reset`、`checkout-remote` 与 `completion` 的启用状态

#### 场景:通过注释设置子菜单修改模板与旧代码策略
- **当** 用户进入设置界面的 `注释设置` 栏目
- **那么** 系统必须允许用户继续进入 `新增格式`、`修改格式`、`删除格式` 和 `旧代码处理` 等子菜单
- **并且** 用户不得只能在同一页长字段列表中完成全部注释相关配置

### 需求:代码文件类型必须支持层级化多选
设置界面的注释配置必须提供“代码文件类型”层级化多选入口，禁止要求用户把 `pattern=renderer;...` 原始字符串作为主要编辑方式。代码文件类型入口必须作为标准子菜单参与层级导航，按语言分类展示子项，并支持分类层与扩展名层之间的进入、返回和多选切换。

#### 场景:通过标准子菜单进入代码文件类型选择
- **当** 用户在 `注释设置` 中选中“代码文件类型”并按下 Enter
- **那么** 系统必须进入代码文件类型子菜单，至少展示 `C/C++`、`Java`、`JavaScript`、`Rust` 和 `Kotlin` 五个分类
- **并且** 该入口必须遵循与其他 setup 子菜单一致的 Enter / ESC 导航语义

#### 场景:在分类层与扩展名层之间往返
- **当** 用户位于代码文件类型分类层并选中某个语言分类后按下 Enter
- **那么** 系统必须进入该分类的扩展名列表
- **并且** 用户在扩展名层按下 ESC 时，系统必须返回分类层而不是直接关闭整个 setup
