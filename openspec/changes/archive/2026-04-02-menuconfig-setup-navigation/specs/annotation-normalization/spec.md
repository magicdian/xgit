## 新增需求

### 需求:系统必须支持按字段标识展开运行时上下文占位符
系统必须允许模板按运行时字段标识展开上下文字段值；对于配置中定义的任意运行时字段，只要该字段在本次执行时被采集到值，模板就必须能够通过同名占位符引用它，而不是仅支持固定的 `reason`、`reference_kind` 和 `reference_value` 三个占位符。

#### 场景:模板展开自定义字段占位符
- **当** 有效配置定义了运行时字段 `ticket`
- **并且** 某个注释模板中包含 `{ticket}`
- **并且** 用户本次执行 annotate 时填写了 `ticket = XP-123`
- **那么** 渲染后的注释文本必须把 `{ticket}` 展开为 `XP-123`

### 需求:系统必须兼容旧版表单字段与引用类型配置
当项目仍使用旧版的 `annotate.form.fields = ["reason", ...]` 与 `annotate.reference_kinds = [...]` 配置时，系统必须在运行时把它们兼容映射为新的结构化字段定义，而不是因为缺少新结构就拒绝执行 annotate。

#### 场景:仅存在旧版 fields 与 reference_kinds 配置
- **当** 有效配置中仍使用旧版 `annotate.form.fields` 与 `annotate.reference_kinds`
- **那么** 系统必须继续按这些配置采集运行时上下文
- **并且** 系统不得因为未显式声明结构化字段定义而拒绝执行 annotate

## 修改需求

### 需求:运行时上下文必须按策略表单采集
注释规范化命令必须根据有效策略配置中的结构化字段定义，在每次执行时采集本次变更的上下文信息，而不是把这些动态值固定保存在长期配置中；字段定义必须至少支持字段标识、显示标签、字段类型和是否必填等属性，禁止要求 setup 继续把运行时上下文绑定到固定的 `reference_kind` / `reference_value` 文本对。

#### 场景:按默认引用字段采集本次上下文
- **当** 当前策略定义了 `reason`、`reference_kind` 和 `reference_value` 三个默认运行时字段
- **那么** 系统必须在执行时按字段定义提示用户填写这些值
- **并且** `reference_kind` 的候选值必须来自有效配置中的引用类型集合

#### 场景:按自定义字段定义采集本次上下文
- **当** 当前策略新增了自定义字段 `module`
- **并且** 该字段被声明为本次 annotate 必须采集的运行时字段
- **那么** 系统必须在执行时提示用户填写 `module`
- **并且** 系统不得因为该字段不是 `reason`、`reference_kind` 或 `reference_value` 之一就忽略它
