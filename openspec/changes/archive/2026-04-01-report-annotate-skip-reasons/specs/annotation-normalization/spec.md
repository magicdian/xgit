## ADDED Requirements

### 需求:系统必须显式汇总未格式化文件及原因
当 annotate 完成候选文件处理后，系统必须分别报告“已渲染文件”和“未格式化文件”的结果；当存在未格式化文件时，系统必须在结束阶段输出逐文件清单与原因，不得只保留模糊的总分母或依赖零散的中途跳过日志。

#### 场景:摘要区分已渲染与未格式化文件
- **当** annotate 处理了一批候选文件，其中只有部分文件成功进入渲染流程
- **那么** 系统必须在结束摘要中分别输出已渲染文件数量和未格式化文件数量
- **并且** 系统不得只输出会把未格式化文件混入分母的单一成功计数

#### 场景:不支持的文件类型进入未格式化清单
- **当** annotate 候选文件中包含 `networkmgr/routemgr/Android.bp`
- **并且** 该路径既未命中当前有效 `annotate.file_rules`，也不属于系统内置代码文件类型目录
- **那么** 系统必须在结束阶段把该文件列入未格式化清单
- **并且** 原因必须明确表示该类型当前不受支持

#### 场景:已知但未启用的内置后缀进入未格式化清单
- **当** annotate 候选文件中包含 `foo.cpp`
- **并且** `*.cpp` 属于系统内置代码文件类型目录
- **并且** 当前有效 `annotate.file_rules` 未启用 `*.cpp`
- **那么** 系统必须在结束阶段把该文件列入未格式化清单
- **并且** 原因必须明确表示当前设置未开启该后缀功能，而不是“不支持该类型”或“未匹配到文件规则”

#### 场景:命中未实现渲染器的文件进入未格式化清单
- **当** 某个候选文件命中了当前有效 `annotate.file_rules`
- **并且** 该规则对应的 renderer 尚未实现
- **那么** 系统必须在结束阶段把该文件列入未格式化清单
- **并且** 原因必须明确表示命中了尚未实现的渲染器

#### 场景:全部文件成功渲染时不输出未格式化清单
- **当** annotate 的所有候选文件都成功完成渲染
- **那么** 系统必须在结束摘要中把未格式化文件数量报告为 `0`
- **并且** 系统不得额外输出未格式化文件清单
