## 新增需求

### 需求:设置界面必须为旧版注释策略提供可迁移的模板编辑入口
当用户打开仍使用旧 `annotate.policies.*` 的配置时，设置界面必须把它们归一化为可编辑的起始模板和结束模板字段展示给用户，禁止要求用户先手工改写配置文件后才能继续使用设置界面。

#### 场景:打开仅包含旧版策略的项目配置
- **当** 用户打开一个只配置了旧 `annotate.policies.modify` 的项目设置
- **那么** 注释策略栏目必须显示可编辑的 `modify` 起始模板字段和值
- **并且** 系统必须同时显示兼容生成的 `modify` 结束模板字段，而不是把结束模板留空或隐藏

## 修改需求

### 需求:设置界面必须暴露核心配置栏目
设置界面必须至少允许用户查看和修改功能使能开关、push 设置占位项、注释策略设置、代码文件类型、注释渲染行为和身份信息；在注释策略设置中，系统必须暴露 `add`、`modify` 和 `del` 各自的起始模板与结束模板配置入口。

#### 场景:修改注释策略相关配置
- **当** 用户进入设置界面的注释策略栏目
- **那么** 系统必须允许用户编辑运行时表单字段、引用类型定义、代码文件类型选择、注释渲染行为开关，以及 `add`、`modify`、`del` 三类注释块各自的起始模板和结束模板
- **并且** 用户不得只能通过固定的单段策略文本间接表达结束模板
