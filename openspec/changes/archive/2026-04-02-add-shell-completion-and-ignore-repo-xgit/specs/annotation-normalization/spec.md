## 新增需求

### 需求:annotate 命令必须忽略仓库级 .xgit 目录
当 `xgit annotate` 处理候选文件或执行 `--latest-commit` 前置校验时，系统必须忽略当前 Git 工作区根目录下 `.xgit/` 及其子路径；但对于其他源码或普通未跟踪文件，系统仍必须维持原有的处理与阻塞行为。

#### 场景:默认 annotate 模式不得把 .xgit 纳入候选文件
- **当** 当前 Git 工作区根目录存在 `.xgit/` 及其内容
- **并且** 用户执行默认 `xgit annotate`
- **那么** 系统必须不把 `.xgit/` 下的任何文件纳入注释候选集合

#### 场景:仅存在仓库级 .xgit 配置目录时允许继续 latest-commit
- **当** 当前 Git 工作区中除仓库根目录 `.xgit/` 及其内容外不存在其他未提交改动
- **并且** 用户执行 `xgit annotate --latest-commit`
- **那么** 系统必须允许继续 latest-commit 模式的注释规范化流程

#### 场景:存在其他未跟踪文件时仍然拒绝 annotate latest-commit
- **当** 当前 Git 工作区中除了仓库根目录 `.xgit/` 外，还存在其他未跟踪或已修改文件
- **当** 用户执行 `xgit annotate --latest-commit`
- **那么** 系统必须拒绝执行
- **并且** 系统必须继续提示工作区当前不干净

#### 场景:忽略 .xgit 时仍继续使用仓库级配置
- **当** 当前项目的有效配置来自 `<git-root>/.xgit/config.toml`
- **并且** `.xgit/` 是 annotate 处理范围中唯一会被识别到的仓库级目录
- **当** 用户执行 `xgit annotate` 或 `xgit annotate --latest-commit`
- **那么** 系统必须继续按项目级配置参与本次 annotate 的有效配置合并
- **并且** 系统不得因为忽略 `.xgit/` 脏状态而回退到仅使用全局配置或默认配置
