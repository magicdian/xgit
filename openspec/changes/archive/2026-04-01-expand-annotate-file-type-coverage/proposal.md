## 为什么

当前内置代码文件类型目录只覆盖 `.c`、`.h`、`.cpp`、`.java`、`.js`、`.rs` 和 `.kt`，这让不少实际代码文件会在 `xgit annotate` 中被直接跳过，例如用户已经遇到的 `*.hpp`。既然 setup 已经把“代码文件类型”作为结构化入口暴露出来，就应该尽快把当前已接入语言族中的常见代码扩展名补齐，避免“明明是代码文件却提示未匹配规则”的体验落差。

## 变更内容

- 审计当前内置代码文件类型目录，仅聚焦“代码文件”范围，明确将 `Android.bp` 等构建/配置文件排除在本次变更之外。
- 扩充现有已接入语言分类中的内置扩展名覆盖，重点补齐当前明显缺失但属于代码文件的常见变体，例如 C/C++ 的头文件/实现文件扩展名变体，以及 JavaScript、Kotlin 家族中的常见脚本或模块代码扩展名。
- 调整 setup 的代码文件类型选择器、默认规则集和配置回写逻辑，使扩展后的内置类型可以被正确展示、选择、保存和回读，同时继续保留未知自定义规则。
- 为新增文件类型匹配补充回归测试，并把项目版本更新为 `2604.1.3`。

### 修改功能
- `interactive-setup`: 代码文件类型选择器需要展示更完整的内置代码扩展名集合，并保持结构化选择与 `annotate.file_rules` 的双向映射稳定。
- `annotation-normalization`: 文件规则匹配需要覆盖扩充后的代码文件扩展名集合，确保这些代码文件会进入现有行注释块渲染流程而不是被误跳过。
- `versioning-source-unification`: 本次发版目标需要更新为 `2604.1.3`，并继续要求版本信息统一来源于 `Cargo.toml` 的 `package.version`。

## 影响

- `xgit/src/code_file_types.rs` 需要扩展内置分类条目与默认选择统计。
- `xgit/src/config.rs` 与 `xgit/config/default.toml` 需要同步扩充默认 `annotate.file_rules` 并更新版本号来源值。
- `xgit/src/setup_ui.rs`、多语言资源和相关测试需要更新，以适配新增的文件类型展示与回写结果。
- 注释匹配回归测试与版本输出测试需要补充或更新，确保新增代码格式可识别且 `--version` 输出为 `2604.1.3`。
